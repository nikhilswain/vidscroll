## Set it up

<Steps>

1. **Install vidscroll.**

   <PackageTabs pkg="vidscroll" />

2. **Put the video in `public/`.** A file at `public/videos/hero.mp4` is served
   at `/videos/hero.mp4`.

3. **Use `ScrollVideo` in a page.** No `"use client"` needed:

   ```tsx title="app/page.tsx"
   import { ScrollVideo, Section } from "vidscroll";

   export default function Page() {
     return (
       <main>
         <ScrollVideo src="/videos/hero.mp4" length="400vh" easing="inOutSine">
           <Section start={0} end={0.3}>
             <h2>Doors close</h2>
           </Section>
         </ScrollVideo>
       </main>
     );
   }
   ```

</Steps>

## Server component or client component?

Both work, and the video behaves exactly the same either way. vidscroll's
components are marked `"use client"` inside the package, so when you use them
from a server component, Next.js treats them as client components
automatically. What changes is only what you can pass to them.

<Table>
  <thead>
    <tr><th></th><th>From a server component</th><th>From your own client component</th></tr>
  </thead>
  <tbody>
    <tr><td>Rendered on the server</td><td>Yes</td><td>Yes, Next.js renders client components on the server too</td></tr>
    <tr><td>Where the video runs</td><td>In the browser, after the page loads</td><td>The same</td></tr>
    <tr><td>Props you can pass</td><td>Plain data: strings, numbers, booleans, objects</td><td>Anything, including functions</td></tr>
    <tr><td>Hooks</td><td>Not available</td><td>Available inside <code>ScrollVideo</code></td></tr>
    <tr><td>Scrolling and loading</td><td>Identical</td><td>Identical</td></tr>
  </tbody>
</Table>

So start in a server component, and move to a client component only when you
need one of these:

- a custom `easing` function (a preset name such as `"inOutSine"` works
  anywhere)
- `onLoad`, `onError` or a `loader` function
- the hooks `useScrollVideo`, `useScrollVideoState` or `useScrollVideoUpdate`

## Using functions and hooks

Put the scroll video in your own component that starts with `"use client"`,
then use that component from any page:

```tsx title="app/hero.tsx"
"use client";

import { ScrollVideo, Section, useScrollVideoState } from "vidscroll";

function Timecode() {
  const { time } = useScrollVideoState();
  return <p>{time.toFixed(1)} s</p>;
}

export function Hero() {
  return (
    <ScrollVideo
      src="/videos/hero.mp4"
      length="400vh"
      easing={(t) => t * t}
      onLoad={({ source }) => console.log("served as", source)}
    >
      <Section start={0} end={1}>
        <Timecode />
      </Section>
    </ScrollVideo>
  );
}
```

```tsx title="app/page.tsx"
import { Hero } from "./hero";

export default function Page() {
  return <Hero />;
}
```

Hooks work in any component rendered inside `ScrollVideo`, like `Timecode`
above.

## What the server sends

Nothing video-related happens on the server: the file is never fetched there.
The server sends the markup for the block, the first frame (or your `poster`)
and the loading bar. In the browser, React takes over and vidscroll starts
downloading the video.

<Callout title="The block grows once when it starts">
  Until the JavaScript runs, the block is one screen tall. It grows to its
  full scroll length as soon as the component starts, so content below it
  moves down once at that point.
</Callout>
